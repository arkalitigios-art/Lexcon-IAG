# Modelo de datos inicial

La implementación SQLite está organizada alrededor de estas áreas: institución/usuarios/membresías/sesiones; reglamentos, versiones y archivos de reglamento; expediente, fases, asignaciones y bloqueos; documentos lógicos, versiones, archivos y actuaciones de fase; tareas, alertas, auditoría y trabajos diferidos. La institución conserva además estado de servicio (`ACTIVE`, `SUSPENDED_ARREARS` o `ENDED`), observación administrativa y fecha de cambio de estado.

Las tablas usan claves foráneas y los accesos se controlan en la capa de autorización. La base conserva versiones documentales independientes y referencias de aprobación, firma u observación a una versión exacta. `process_stage_actions` conserva la fase, actor, observación y fecha de cada transición. La referencia opcional de publicación se conserva separada de la confirmación institucional trazable; no existe publicación automática.

Las entidades de mercado, precontractual, ofertas, evaluación, formalización, ejecución y cierre ya disponen de tablas estructurales relacionadas con el expediente y sus versiones documentales. El análisis de mercado agrega `document_extractions`, vinculada de forma única a una versión de documento para conservar el texto privado extraído, el parser utilizado, el estado y sus incidencias, y `market_comparisons`, que conserva los valores fuente y el rango reproducible de cada ítem comparable. `market_quote_items` mantiene los ítems identificados por cotización. Estas tablas registran hechos de lectura y cálculo; no almacenan recomendaciones, promedios ni decisiones jurídicas.
